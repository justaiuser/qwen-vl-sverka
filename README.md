# 📊 Автоматическая сверка актов бухгалтерии (1C ⟷ Скан / PDF)

Интеллектуальная система автоматической сверки актов взаимных расчетов между бухгалтерской выгрузкой из **1С:Предприятие (Excel)** и первичными документами контрагентов (**сканы, фотографии, PDF**).

Система работает на **локальной мультимодальной нейросети Qwen3-VL** через Ollama, обеспечивая конфиденциальность бухгалтерских данных без передачи во внешние облачные сервисы.

---

## 🚀 Основные возможности

1. **Парсинг выгрузок 1С (.xlsx, .xls)**:
   - Распознает стандартные формы актов сверки 1С:Бухгалтерия (версии 3.0, 2.0, УТ, ERP, КА).
   - Извлекает период, реквизиты сторон (Наша организация, Контрагент).
   - Считывает начальное сальдо, строки операций (Дата, Номер и наименование документа, Дебет, Кредит), итоговые обороты и конечное сальдо.
   - Корректно обрабатывает объединенные ячейки, неразрывные пробелы и рублевое форматирование.

2. **Распознавание сканов и PDF контрагентов (Qwen3-VL Vision)**:
   - Поддерживает как многостраничные сканированные PDF, так и изображения (PNG, JPG, TIFF).
   - Гибридный режим: мгновенный парсинг цифровых PDF с текстовым слоем + интеллектуальный OCR через локальную модель **Qwen3-VL** при сканах и фото документов.
   - Автоматически находит таблицу операций, реквизиты и итоговые суммы.

3. **Бухгалтерский алгоритм сопоставления (Многоуровневый Matcher)**:
   - **Зеркальность проводок РФ**: Дебет 1С сопоставляется с Кредитом контрагента, Кредит 1С — с Дебетом контрагента.
   - **Тир 1 (Точное совпадение)**: Совпадение суммы цент-в-цент, номера документа и даты (в пределах настраиваемого окна допуска).
   - **Тир 2 (Сдвиг даты)**: Сумма и номер совпали, но дата платежа или отгрузки сдвинута.
   - **Тир 3 (Несовпадение номеров)**: Сумма и дата сходятся, но номер документа у контрагента записан по-другому (например, номер счета вместо номера УПД).
   - **Тир 4 (Расхождение в сумме)**: Документ найден с обеих сторон, но суммы отличаются (например, частичная оплата или разногласия по стоимости).
   - **Тир 5 (Отсутствующие документы)**: Четко разделяет операции:
     - *«Только в 1С»* — документ проведен у нас, но не отражен у контрагента.
     - *«Только у контрагента»* — документ есть в акте контрагента, но отсутствует в нашей 1С.

4. **Формирование отчета в Excel (.xlsx)**:
   - **Лист «Сводка»**: Карточки организаций, периода, сальдо на начало и конец, обороты и итоговый вердикт.
   - **Лист «Расхождения»**: Подробная ведомость всех разногласий с цветовой маркировкой.
   - **Лист «Сверенные»**: Список сошедшихся операций.
   - **Лист «Все операции»**: Полная сравнительная таблица (Side-by-Side).

5. **Современный Web-интерфейс**:
   - Drag & Drop загрузка файлов 1С и сканов.
   - Кнопка моментальной демонстрации на готовых тестовых данных.
   - Фильтры («Все», «Только расхождения», «Сверенные»).
   - Живой поиск по номеру или сумме.
   - Скачивание протокола в один клик.

## ⚡ Быстрый старт

### 1. Запуск Web-интерфейса

Запустите сервер:
```bash
python run_web.py
```
После запуска откройте в браузере: **http://127.0.0.1:8080**

Вы можете нажать кнопку **«✨ Загрузить демо-пример»**, чтобы увидеть сверку в действии за несколько секунд!

### 2. Использование через CLI (консоль)

```bash
python cli.py reconcile --excel "путь_к_1с.xlsx" --pdf "путь_к_акту.pdf" --output "Протокол.xlsx"
```

Дополнительные параметры:
- `--tolerance 5`: допустимая разница в датах (по умолчанию 5 дней).
- `--model qwen3-vl:4b-instruct`: выбор модели Ollama (`qwen3-vl:4b-instruct`, `qwen3-vl:8b-instruct`, `qwen3-vl:2b-instruct`).
- `--force-ocr`: принудительное распознавание через Qwen-VL даже при наличии текстового слоя.
